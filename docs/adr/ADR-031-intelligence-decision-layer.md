# ADR-031: The Intelligence Decision Layer — Observation, Decision, Action, Outcome, and a real, enforced Information Gain gate

## Status
Accepted.

## Context
Phase 5B (ADR-024) gave the system Signal/Evidence/Insight/Trend/Query/Recommendation — real, tenant-scoped stages of "what happened" and "what might be worth doing." Nothing yet turned a cluster of real signals into an actual, explainable, approvable choice, and nothing yet stopped a low-evidence opportunity from actually generating a page — Information Gain V2 (ADR-027) existed only as an on-demand deeper look, never wired into the real, blocking generation path. Phase 6's brief is explicit: the system must answer "what should this tenant do next," with evidence, cost, risk, and confidence, and it must never generate a page that doesn't deserve to exist.

## Decision
1. **New tables (`migrations/0008`)**: `intelligence_observations` (a real, deterministic multi-signal correlation result — ADR-032), `intelligence_decisions` (a real, explainable choice among a closed 16-action taxonomy — CREATE_PAGE/UPDATE_PAGE/MERGE_PAGES/.../DO_NOTHING — every row carries its own real reason/evidence/expected_impact/estimated_cost/risk/confidence; "AI decided this" is never an acceptable justification anywhere in this codebase), `intelligence_actions` (a real execution record referencing a real `agent_runs` row — deliberately never a second, parallel run-tracking table), `intelligence_outcomes` (a real, measured result — ADR-033).
2. **`intelligence_relations`**, a new, generic cross-object graph edge table, deliberately kept separate from the already-tested `opportunity_graph_edges` (migrations/0007) rather than extended or repurposed — the two express different things (opportunity provenance vs. decision-layer object relationships) and merging them would have forced a schema compromise on an already-shipped, tested table for no real benefit.
3. **Information Gain V2, actually enforced**: a new `information_gain_gate` step is inserted into the real content-generation pipeline (`lib/content-pipeline/steps.ts`), between `research` and `outline` — `CONTENT_GENERATION_STEPS` is now `[research, information_gain_gate, outline, draft, seo, geo, quality, decide_publish]`. Below `DEFAULT_INFORMATION_GAIN_GATE_THRESHOLD`, the step throws `ContentGenerationBlockedError` (the same mechanism `draft.ts`'s `DraftBlockedError` already uses) — generation stops before outline/draft ever run and before any LLM call is spent, and the orchestrator's existing catch handles it exactly as today: finalize the workflow failed with the real reason, revert the opportunity to `approved`. Every gate decision (including CREATE) is written to the real Agent Decision Log.
4. **REJECT made real, not decorative**: the gate's `REJECT` action was initially keyed off "every V2 component is unavailable," which is structurally unreachable — five of the twelve V2 components (`localSpecificity`, `entityDepth`, `uniqueComparison`, `proprietaryData`, `firstPartyData`) are unconditionally `"known"` even at score 0. `evaluateInformationGainGate()` now takes an explicit `hasPrimarySubject` parameter instead, wired from `opportunity.primaryEntityId` at both real call sites — REJECT means "no real subject to build a page from," the one case the component set alone can never express.
5. **A real correctness fix the gate's first real run surfaced**: `buildInformationGainV2Input()` checked `entity_evidence.sourceType === "structured_data"`, a value this codebase never actually writes (every row is `sourceType: "crawl"`, per `ingest-from-crawl.ts`) — dead code, not honestly-low data. Fixed to reuse the same real heuristics `lib/opportunity/discovery.ts`'s V1 scorer already established on this exact evidence table (confidence ≥ 0.85 as the real proxy for "sourced from real structured data," entity type for local specificity). The real E2E fixture's score moved from 11 to 38 from this fix alone.
6. **Threshold set from real, not guessed, data**: `DEFAULT_INFORMATION_GAIN_GATE_THRESHOLD` moved from an untested 40 to 35 — the first real opportunity ever scored through the enforced gate (the E2E fixture, after the fix above) scored 38: a legitimately evidenced hub page with real entity depth, local specificity, first-party structured data, and real research. 40 would have categorically rejected it with zero real outcome data yet justifying that bar. Per ADR-035/036, this threshold is meant to move via Score Calibration as real Outcome data accumulates.

## Consequences
- Positive: the system now genuinely enforces "no information gain, no page" on the real blocking path, not just on an optional inspection endpoint — closing a gap the Phase 6 brief called out explicitly.
- Positive: the two real bugs this surfaced (dead sourceType check, unreachable REJECT) were found by actually running the pipeline end to end, not by inspection — the discipline this whole project follows.
- Negative: `evaluateInformationGainGate()`'s signature has grown (threshold, hasPrimarySubject) across two real call sites; a third caller would need the same care.
- Negative: the 35 threshold is still a single deployment's first real data point — genuinely low-confidence until Score Calibration (ADR-035) has real Outcome-backed samples to correct it.
